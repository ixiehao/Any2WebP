# 开发与验证

## 本机编译

需要 Apple Silicon Mac、macOS 26.0 或更新版本、当前系统对应的 Xcode 命令行工具、Rust 1.100.0、Python 3.9 或更新版本，以及 Homebrew 的编解码依赖。界面测试使用 Node.js 22 或更新版本。本机验证使用 libwebp 1.6.0 和 GIFLIB 6.1.3。应用和处理进程的最低系统版本均取自 Tauri 配置。

```sh
brew install webp giflib ffmpeg
./Scripts/build-app.sh
open dist/Any2WebP.app
```

脚本使用支持 WebAssembly 的 Clang 和 Rust 工具链自带的 `rust-lld` 编译画质滤镜。若 Xcode Clang 缺少 `wasm32` 目标，安装 Homebrew 的 `llvm`，再设置 `export ANY2WEBP_WASM_CLANG="$(brew --prefix llvm)/bin/clang"`。原生处理进程仍由 Xcode Clang 构建。已有应用包可以先归档，或通过 `ANY2WEBP_DIST` 指定另一输出目录。

构建会读取锁定的 Cargo 依赖，把第三方版本、许可原文及匹配版本的源码链接写入应用的 `Contents/Resources/RUST-NOTICES.txt`。项目 MIT 许可证、原生库和图标声明及 libwebp 专利授权也随包分发。遇到上游 crate 缺许可原文时，在 [许可补充目录](licenses/README.md)登记其锁定版本与来源。

## 代码入口

| 路径 | 职责 |
| --- | --- |
| `app/` | 队列、参数和预览。一条时钟驱动两个画布，各自按源帧延时定位。 |
| `src-tauri/` | macOS 窗口、文件选择、串行任务、进程取消和排他落盘。 |
| `src-tauri/src/video.rs` | 选取实际视频轨道，按片段、帧率、等比尺寸解码为 RGBA。预览和编码使用同一抽帧规则。 |
| `src-tauri/src/video_tools.rs` | 预览、导出和界面体检共享 FFmpeg/ffprobe 解析。验证来自同一安装位置的两个可执行文件，必要时由用户发起 Homebrew 安装或修复。 |
| `engine/codec.c` | GIFLIB 处理 GIF，libwebp 处理 WebP，ImageIO 读取其他图片。合成每帧的完整画布。WebP 使用差异区域编码，GIF 为每帧生成调色板。最终输出重新解码核对。 |
| `engine/adjustment.c` | 图片、动图和视频共用的 RGBA 画质滤镜。原生版用于完整预览和导出，WebAssembly 版用于滑杆和片段拖动时的预览。 |
| `engine/samples/planet.gif` | 原型自制的透明合成动图，24 帧、非等长帧、播放 3 次。 |
| `Tests/test_codec.py` | 用程序生成的像素和独立 RIFF 读取验证媒体语义。 |

## 回归

WebP 夹具由 Homebrew 的 `img2webp` 和 `cwebp` 生成。CI 与本地使用同一个回归入口。

```sh
./Scripts/verify.sh
```

回归覆盖局部帧、清除背景、恢复上一帧、0/10 ms 帧、无循环扩展、有限/无限循环、8 位半透明、目标达标与未达标、保留更小的原 WebP，损坏输入、APNG 独立封面与子帧、JPEG 方向、多尺寸 ICO，以及静态图像转换。

本机另用合成样本验证 HEIC、AVIF、PSD、JPEG 2000 和 JPEG XL 解码与转出。隔离的打包应用验证了 WebP 批量目标体积、损坏项后继续处理、转换沿用原名、压缩加后缀、同名避让和前后画布同步。

视频回归使用合成 MP4、MOV、WebM，覆盖非帧边界剪切、位图宽高、末帧时长、旋转、VP9 Alpha 和文件体积。将 `ANY2WEBP_TEST_VOLUME` 指向临时测试卷，并通过 `ANY2WEBP_TEST_APNG` 提供一张带动画的 PNG，可以同时验证 GIF 和 APNG 的真实落盘、同名避让及重新解码。

0.2.0 在临时 ExFAT 卷上复现了独占重命名的 `os error 45`。同一卷上的兼容路径通过了 GIF、APNG 的同名导出、最终文件回读和时序核对。

0.2.1 会取消过时的预览请求。导出完成后，若文件状态和参数一致，界面沿用原片预览和当前播放位置，仅加载成品。原文件或成品有变化时，界面会提示重新处理。媒体回归覆盖后台进程取消、同路径替换和预览数据状态校验。

0.2.2 在视频设置中增加原视频时间轴。拖动时更新秒数和选区，松手时沿用既有的视频参数校验与预览流程。若更改了已导出的选区，重新导出后可比较两侧。方向键每次调整 0.1 秒，按住 Shift 每次调整 1 秒。

0.2.3 从原视频均匀取八张缩略图。拖动手柄时，单帧预览先显示邻近缩略图，再使用原视频对应时间的画面。后台只保留一个正在执行和一个等待执行的单帧请求。松手、取消或切换文件会清理单帧请求，导出仍沿用已提交的片段参数。回归用红蓝切换视频验证 MP4、MOV 和 WebM 的取帧时序。

0.2.4 为每个视频保存独立的时间轴可见范围，最小显示范围为 1 秒。缩放和横向滚动只更新缩略图，过时的取图请求会取消。缩略图从可见范围均匀采样，拖动手柄使用相同的时间刻度；输入视野外的边界时，时间轴会随之移动。

0.2.5 在放大的时间轴上按住手柄靠近边缘即可滚动，速度随鼠标接近边缘而增加。滚动过程中持续更新选区、秒数和对应单帧，停止后更新缩略图，松手时提交片段。SDR 视频画质选项参考 MP4Flow 的暗部曲线和逐帧降噪，加入有阈值和幅度上限的轻度锐化。处理后预览与导出共用同一帧处理流程，保留 Alpha 通道与帧时序。

0.2.6 可从选区中间拖动整段，在视频两端限制位移，保持片段长度。拖动中以鼠标抓取点对应的帧做左右对比。画质设置支持所有现有输入格式，每个文件单独记录三项强度。拖动滑杆时先调整预览尺寸下的像素，滑杆停稳后从原始解码帧按导出顺序计算，再缩小为完整对比预览。画质调整针对 WebP 导出使用的 8 位 RGBA 画面。

0.2.8 应用采用浅蓝三栏布局与 01B 图标，通用操作图标来自 Tabler Icons Outline v3.49.0。界面文案集中在 `app/i18n.js`，macOS 首选语言按顺序匹配，手动选项由 WebView 持久化。菜单、已保存的处理状态和错误提示随语言切换。有限播放次数超出 WebP 的 16 位字段时限制为 65,535，原始与成品播放次数分别记录，供界面显示调整提示。

0.2.13 从 DMG 复制并启动应用后，通过 macOS「Any2WebP → 检查更新」对 `https://github.com/ixiehao/Any2WebP/releases/latest` 发起匿名 HEAD 请求。实测返回 404，界面显示暂无公开正式版本，顶栏保持空白，三个窗口按钮较旧版下移 16 点。另用隔离应用模拟发现较新版本、断网与限流，在 820 点窗口下核对三种语言的提示和发布页入口，并导出示例 GIF，独立读取确认 24 帧、Alpha 和 3 次播放。正式包的 Developer ID、公证和线上 Release 流程待首次公开发布时执行。

0.2.14 将导出动作和批次进度固定在右栏底部。队列记录各成品的压缩目标和保存位置，失败重试与取消保留上次成功结果。用 820 × 625 的隔离应用验证三语布局、混合批次、失败项重试、取消、目标及位置变更、动图逐帧同步和视频片段导出。另用 503 条队列路径复查去重和列表节点复用。无需缩放的内置 GIF 预览与 0.2.13 逐字节一致。清空队列时两侧隐藏画布缩至 1 × 1。

0.2.15 挂载最终试用 DMG，检查 680 × 430 的实际 Finder 窗口、两个拖拽图标以及背景引用。从镜像复制应用后，经原生菜单确认本机 FFmpeg 与 ffprobe 版本，并导出示例 GIF。隔离应用以假 Homebrew 验证缺工具、安装失败、命令成功但仍缺 ffprobe，以及复检成功后原队列视频自动恢复预览和导出。测试覆盖三语，未改动本机 Homebrew。

低帧率裁剪回归使用实际 MP4 与 WebP，核对稀疏帧在显示区间内的取样像素及 500 ms 的完整时序。外部进程测试覆盖超时或取消时子进程持有管道、正常退出后的后台进程，以及双管道限长读取。APFS 落盘用例和模拟专有重命名失败用例通过。本机暂时无法创建 ExFAT 测试镜像，本轮未在 ExFAT 上实测。

0.2.16 视频片段选择移入独立剪切窗。窗口内的源画面、播放位置和起止时间码使用源视频时间。源帧微调按 ffprobe 的源帧率计算，确认时按 WebP 的帧数和内存限制校验。源画面采用无声播放，预读使用至多两秒的低分辨率帧段。隔离应用在 820 × 625 窗口验证三语、时间码、±5 帧、缩略图、缩放后拖到边缘自动滚动、跨缓冲段播放、取消和重复确认。20 FPS 红蓝 MP4 选择 4.125–6.625 秒后，12 FPS 导出 30 帧、2,500 ms，独立像素回读确认旧成品首帧为红、新成品首帧为蓝。

0.2.17 主窗口的视频片段改为紧凑控制栏，帧率和长边使用预设菜单。隔离应用在简中、英文和日文下测得 1240 点窗口内栏高 44 点，820 点窗口内栏高 56 点。实测小尺寸视频默认使用原尺寸，切换素材保留各自参数，选择 15 FPS、320 px 后预览和 WebP 均为 320 × 180，3 秒内含 45 帧。导致片段不足两帧的预设继续显示校验提示。

0.2.18 剪切窗口按源长、导出帧率、输出画布、600 帧及 192 MiB RGBA 帧预算显示最长可选时长。820 × 625 的隔离窗口验证简中、英文、日文、继承主窗口播放位置、10／12／20 秒快选、缩放后自动显示选区、时长超限及片尾缩短。640 × 360、12 FPS 的测试素材验证上限 18.167 秒，输入多 1 ms 时阻止确认。快选到片尾的 27–28 秒区间实际导出 12 帧和 1,000 ms。

0.2.19 视频解码与 WebP 回读的帧预算提高到 384 MiB，剪切窗口从后端读取预算。隔离应用以 640 × 360、24 FPS 预览并导出 10 秒素材，240 帧的临时 RGBA 数据约 210.94 MiB。重新加入队列核对 WebP 的时序与两端像素。相同参数下确认 18.167 秒允许选择，18.168 秒提示超限。

0.2.20 视频解码与 WebP 回读的预算提高到 512 MiB。视频转 WebP 的最高帧率为 30 FPS，常规默认 12 FPS。30 FPS 下需要至少 34 ms 才能取到两帧。隔离应用验证 960 × 540、24 FPS 的 10 秒片段预览、导出及重新打开，成品 240 帧、10,000 ms，对应约 474.61 MiB 的原始 RGBA 数据。另验证同设置时长上限 10.750 秒，以及 50 ms 源片在 30 FPS 下的两帧预览。

### 0.2.23 编码性能回归

在同一台 Apple Silicon Mac 上，以 0.2.22 试用包中的引擎为基线。测试输入为 640 × 360、12 FPS、360 帧的 RGBA 合成动画。背景颜色为 `(22,57,96,255)`，72 × 40 矩形的颜色为 `(229,144,67,255)`，第 `i` 帧的坐标为 `(i × 9 mod 568, i × 7 mod 320)`，帧序从零开始。先暖机一次，再交替运行两个版本各三次。下表耗时覆盖引擎读取 RGBA、编码、逐帧校验和落盘。用 macOS `/usr/bin/time -l` 记录峰值 RSS，取三次的中位数。

| 引擎路径 | 中位耗时（0.2.22 → 0.2.23） | 峰值 RSS（0.2.22 → 0.2.23） |
| --- | --- | --- |
| 无损 WebP | 0.357 → 0.192 秒 | 654.0 → 334.0 MiB |
| GIF，目标 1 KiB | 2.809 → 1.167 秒 | 652.3 → 330.2 MiB |

每条路径的新旧文件 SHA-256 与解码元数据一致。GIF 用例的目标体积低于成品体积，用于覆盖多个调色板档位，提升幅度取决于帧内容和压缩目标。0.2.23 还复用了连续操作中的视频探测，并在素材或工具文件变化时重新探测。
